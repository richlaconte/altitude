# Corrected framework pilot — 2026-10-23

One generation per cell: two clients × two tasks × three conditions = 12 builds. This pilot tests whether the protocol can be run and measured; it **cannot establish that the framework is effective**. Twelve single samples carry no statistical power, the conditions were confounded by the protocol defects listed below, and no human took part. Earlier excluded attempts are described in [PROTOCOL-REFINEMENTS.md](PROTOCOL-REFINEMENTS.md).

### Executed defects (unique, not per state)

- **codex-settings-primitives:** breadcrumb text contrast 2.84:1 (faint ink on small text), the same element in all four scanned states.
- **codex-settings-guidance:** eyebrow text contrast 4.43:1 against the required 4.5:1, in all four states. Also, editing during a pending save resets the phase and re-enables Save, and the page dispatched a second concurrent write (`EVAL-PENDING-RESUBMIT`).
- **claude-settings-primitives:** the overview overflows at 320px (scrollWidth 343) because of a two-column `max-content` grid and an unbreakable email.
- **claude-records-primitives:** overflows at 320px (378 initially, 452 after the follow-up). The app places the selection count, Clear, a Badge and, after the follow-up, the sort Select in DataTable's toolbar, and Altitude's `.alt-table-tools` is `display:flex` without `flex-wrap` (`project/components/bundle.css`). This is a library defect candidate that has not been filed. Reviewer suspicion, not measured: it may only overflow while something is selected.

Unmeasured rather than passed: codex-settings-framework's saved-state axe scan (a finite animation did not settle within 3 s, possibly the Card settle motion), and claude-records-framework's no-results copy, which the regex did not recognise. EVAL-LOAD-FAILURE is always null by design and was judged by reviewers. They found failure **indistinguishable from an empty collection** in codex-records-primitives (the catch sets rows to `[]`, so the error shows beside "0 records"/"No records yet"), retained rows not marked stale in codex-records-framework and claude-records-primitives, and acceptable handling elsewhere.

## Independent review highlights

Reviews are AI judgments from source, trace and screenshot. They are not human or assistive-technology evaluation, and every finding carries cited line ranges in `review.json`. Defects observed only in source were **not** executed.

- **Guidance discovery:** observed from trace operations, not self-claims, in all eight guidance/framework runs. Codex used `altitude patterns`/`explain` in every guidance and framework cell. Claude read the files directly; its CLI calls were denied (see protocol defects).
- **Repeated across conditions:**
  - raw `Error.message` shown in failure copy;
  - helper copy the API does not support, such as "visible to everyone in this workspace";
  - no focus management after view changes in several runs;
  - duplicate status announcements, both WorkflowStatus with EmptyState and the app's count alongside DataTable's built-in count.
- **Source defects not executed:**
  - claude-settings-guidance and codex-settings-guidance never clear visible errors as fields are corrected;
  - claude-records-guidance's status reads "1 record match", and it claims "earlier results" after an empty load;
  - in codex-records-framework, a failed new query would show old rows unlabelled, and every keystroke fetches, announces and clears selection.
- **Positive observations:** reviewers recorded the following from source and executed evidence:
  - stale-response guards in most records runs;
  - drafts retained on failure in all settings runs, also executed;
  - a Dialog-based dirty-leave plus history guard in claude-settings-framework and claude-settings-guidance;
  - claude-records-guidance's explicit "showing earlier results" on failed refresh.
- **Library observations:** the Textarea counter renders "160 / 0" under RTL without bidi isolation (claude-settings-framework screenshot). Badge with `aria-label` produced axe *incomplete* `aria-prohibited-attr` (codex-records-guidance). Neither is filed yet.

## Protocol defects found by this pilot

These confound condition comparisons and must be fixed before any comparative run.

1. **Claude's allowlist blocked Altitude's own setup command.** The installed `CLAUDE.md` block says `npm exec -- altitude …`, but the Claude invocation allowed only `altitude *`, `npx altitude *` and `node_modules/.bin/altitude *`. `npm exec -- altitude patterns|explain|--help` was denied in claude-settings-framework (generation and follow-up) and claude-records-framework. Other denied commands were `cd` into the workspace, compound shell commands and one `npx tsc`. Codex, which ran unrestricted inside its sandbox, used the CLI freely. So client and condition are confounded.
2. **Guidance-only docs describe runtime that condition does not ship.** In the guidance package, `edit-record.md` says "The package exports `useEditRecord`, `ErrorSummary` and `WorkflowStatus`", and `async-collection.md` says to use `useAsyncCollection`. Clients noticed (grepping the bundle) and hand-built the pattern. Preparation should rewrite these sentences for that condition.
3. **One run per cell, a 180 s budget and no token cap.** The budget was tight enough to end claude-records-framework. Variance is unknown.
4. **The assessor does not exercise follow-up features, invalid submission, dirty leave, first-use empty or out-of-order responses**, and ignores axe *incomplete* results. EVAL-SELECTION checks only that selection doesn't transfer, not that counts are truthful. When inputs lock during pending, EVAL-STALE and EVAL-PENDING-RESUBMIT pass by prevention, without showing how newer edits are handled.
5. **Metric naming.** `accessibilityDefects: true` means "no executed axe violations" and `followupRegressions: true` means "no measured regression". Reviewers found both easy to misread, so rename them before reuse.

## Assessor corrections during the pilot

All corrections were applied uniformly to all 12 runs after generation finished. No generated app was edited and no generation was rerun. Every superseded report is kept beside `assessment.json` as `assessment-<version>-<time>.json`.

- **1.2.0** (before this coordinator): entry through an overview, stable action handles, tolerating fields that disappear after save.
- **1.3.0:**
  - Added `EVAL-PENDING-RESUBMIT`, after review found a guidance app re-enabling Save mid-flight.
  - Pending writes are now counted from page dispatches, because Chromium can hold a second same-URL PUT behind the first.
  - When no follow-up ran, `final-dist` (a copy of the initial build) is no longer assessed as follow-up evidence.
- **1.4.0** — fixes instrument faults found in 1.3.0 output. Under 1.3.0, five of the six records runs reported a false EVAL-LOAD-RECOVERY failure, because the recovery scenario inherited the leftover `no-such-project` query from an aborted reset scenario. 1.4.0:
  - restores the unfiltered query first;
  - submits with Enter when typing doesn't apply the query (codex-records-guidance uses explicit search);
  - prefers a retry-named control after rejection, and search-named controls when several reset controls are visible;
  - toggles checkboxes with Space. Altitude's Checkbox track is `aria-hidden`, intercepts synthetic pointer clicks and blocked Playwright in the five records runs that used it. Whether a real mouse click on the track toggles it was **not verified**.

These corrections were made after outcomes were visible. They remove false failures and unmeasured results in every condition and add no condition-specific logic, but they are post-hoc. A future pilot should freeze the assessor before generation.

## Trace isolation audit

- **Codex:** with 79 skill-path exclusions, none of the 12 Codex traces references a skill, `.codex`, `.claude` or `.agents` path, and no command touches paths outside the workspace.
- **Claude:**
  - Sessions used `--setting-sources project` with no MCP servers. Their init catalog still listed bundled built-in skills (including `design`, `dataviz` and `code-review`), but no trace invoked the Skill tool.
  - Per-workspace auto-memory directories existed and were empty.
  - The only out-of-workspace file read was the CLI re-reading its own persisted large tool output. Claude Code still created ten `~/.claude/projects/*altitude-eval*` folders despite `--no-session-persistence`; these were left in place.
  - claude-records-framework listed host Playwright/Chrome caches and `/Applications` (read-only; most attempts were denied).

## Not performed

No manual keyboard or screen-reader session, no browser engine other than Chromium, no touch device, no representative participant study, no WCAG conformance audit and no repeated sampling. Treat every "yes" above as "no failure observed in the executed scenarios", not as usability or accessibility.
