# Framework pilot rerun 1 — 2026-10-23

Three samples per cell: 2 clients × 2 tasks × 3 conditions × 3 samples = 36 builds, each followed by a fresh-context follow-up. This is next step 4 from [IMPLEMENTATION.md](../../../docs/framework/IMPLEMENTATION.md), run after the protocol fixes in steps 1–3. It is still a protocol pilot: three samples per cell carry little statistical power, the reviewer was not blind to condition, no human took part, and the confounds listed below remain. **It cannot establish that the framework is effective.**

### Post-hoc assessor correction (2.0.0 → 2.0.1)

The first 2.0.0 assessments reported EVAL-SORT failures in Codex records apps whose sort control is Altitude's `Select`. That control is a button with `aria-haspopup="listbox"`, not a `combobox`, and 2.0.0 clicked it three times as a toggle, which only opens and closes the menu. Choosing an option in the built app sorts the records correctly, so these were instrument faults. Version 2.0.1 operates such a button like a combobox. A fixture test covers it. The correction was applied to all 36 runs, and each run keeps its superseded 2.0.0 report beside `assessment.json`. No other assessor change was made after generation.

### Library defect candidates

- **ErrorSummary target size (new, not filed).** `.alt-error-summary` sets no minimum target size or spacing for its links. With the browser's default line-height, two stacked error links are about 18px tall and fail axe `target-size` (WCAG 2.2 SC 2.5.8) in claude-settings-framework s2 and s3. The same component passed in apps that set a larger body line-height. Hand-built summaries in the guidance condition fail the same way.
- **DataTable toolbar overflow** ([#26](https://github.com/richlaconte/altitude/issues/26), filed earlier today). Two Claude primitives records apps placed search, sort and refresh in `toolbar` and overflowed at 320px (418px and 345px) after the follow-up.

## Independent review highlights

These are AI judgments of source and trace, not human or assistive-technology evaluation. Every finding cites line ranges in `review.json`, and defects seen only in source were not executed.

- **Guidance discovery** was observed in the trace operations of all 24 guidance and framework runs. Codex used `npm exec -- altitude patterns` (and often `explain` and `doctor`) in all 12. Claude read the installed guidance files in all 12 and ran the `altitude` CLI in some.
- **Repeated in most apps, in all three conditions:** the raw `Error.message` from the service shown as failure copy. Apps that filter service messages, such as claude-settings-framework s1 and s3, are the exception.
- **First-load failure shown with the empty state:** codex-records-primitives s1 and s3, claude-records-primitives s1 and s3 (rows set to `[]`, so "No records yet" appears beside the error).
- **Errors not cleared as fields are corrected:** claude-settings-guidance s1 and s2, codex-settings-guidance s3.
- **Unsupported copy:** "visible to everyone in this workspace" style claims the API does not support, in all six Codex settings apps in the primitives and guidance conditions.
- **Duplicate selection counts** (app count plus DataTable's built-in count) in several DataTable apps.
- **Hard-coded colours** instead of tokens in several Codex framework apps; none failed contrast.

## Remaining confounds and limits

- **Claude permission denials remain, and they are uneven:** 20 in primitives runs, 32 in guidance and 37 in framework (generation and follow-up combined). No plain `npm exec -- altitude …` call was denied. The denials are compound or unlisted commands: `cd … && python3`, `npm --prefix … run build`, `grep` over the bundle, and probes for a host browser. Two denied altitude calls were piped into other commands. Guidance and framework runs spend more turns inspecting the package, so they hit the narrow allowlist more often.
- **Instrument gaps (unmeasured, not failed):**
  - follow-up sort in codex-records-guidance s3 (a DataTable column header named "Record name");
  - follow-up description in codex-settings-primitives s3 (two plausible "return to overview" controls);
  - first-use-empty copy phrasings;
  - invalid-error association when Save is disabled.
- **Not blind.** The reviewer generated, assessed and reviewed in one session and knew each condition. Screenshots were not reviewed.
- **Not covered:** a single engine (Chromium), no manual keyboard or assistive-technology session, and no participants.

## Next protocol changes

1. Widen the Claude allowlist to the read-only and build commands agents actually use (`npm --prefix * run build`, `grep *`, `cd * && …`), or run Claude with an equivalent sandbox. Then report denials per condition, aiming for zero.
2. Close the instrument gaps above with fixture tests before the next run, and freeze 2.1.0 before generating.
3. Use blind review: a reviewer who sees only the source and screenshots, with the condition hidden.
4. Increase samples per cell once the remaining confounds are removed. Settings dirty-leave handling is the clearest candidate outcome to power.
