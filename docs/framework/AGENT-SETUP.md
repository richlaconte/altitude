# Connect installed guidance to an agent

Install `altitude-design`, then run the installed binary from the consumer project root. The Node CLI has no runtime React dependency and no install hook. It never writes to a project merely because the package is installed.

```sh
npm exec -- altitude init --client codex
npm exec -- altitude init --client codex --apply
npm exec -- altitude init --client claude --apply
npm exec -- altitude patterns "edit settings" --json
npm exec -- altitude explain ALT-EDIT-001
npm exec -- altitude doctor --json
npm exec -- altitude check --json
npm exec -- altitude init --client codex --remove
npm exec -- altitude init --client codex --remove --apply
```

`init` defaults to a preview, including the exact before/after text. `--apply` applies that preview. `--client all` targets both clients. Repeating setup makes no change. Removal removes only the managed block, restoring surrounding bytes; a file created by setup is removed only if nothing else remains. User-edited managed blocks, malformed markers and symlinks are rejected for manual reconciliation. Existing instructions outside the block are preserved. Run setup again after upgrading the installed package. Use `--cwd PATH` to target an explicit project directory. Resolution uses that directory's installed `altitude-design/package.json`, never the version fetched by a different CLI invocation.

The Codex adapter writes a compact routing block to project `AGENTS.md` (or an existing nonempty `AGENTS.override.md`, which Codex gives precedence); the Claude Code adapter writes it to project `CLAUDE.md`. Neither assumes instruction files under `node_modules` are automatically discovered. The routing block points at version-matched local focused documents rather than importing the complete manual. Because it's read on every turn, it carries only what an agent can't work out for itself: a reminder to prefer the installed docs and declarations to its memory, the rules that hold on every screen, and a compact index of every component (by group, with the path pattern of each component's guide), read on demand. The `agent-setup` check keeps it under 8 KB and verifies that every path it names is installed. Restart the agent session after setup. Confirm Codex reports the project instruction file and Claude Code's `/context` lists it under Memory files; then ask an ordinary product question and check that the relevant pattern is read. Instructions are context, not enforcement, and broader or more specific instructions may affect discovery.

Mechanisms verified against official documentation on 2026-10-23: [Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) describes root-to-working-directory instruction discovery, override precedence and size limits; [Claude Code memory](https://code.claude.com/docs/en/memory) documents project `CLAUDE.md` loading and `/context` inspection. The adapter tests verify files and round trips, not successful behavior of every client release. Claude Code also documents AGENTS.md support; CLAUDE.md remains the explicit adapter target.

`doctor` reports stable rule IDs, observed evidence, expected behavior, repairs and verification. It returns a failing exit code only for deterministic installation/setup defects; service integration and contextual obligations remain visibly unverified. It does not inspect an application's service behavior or certify accessibility. `check [dir]` (default `src`, else the project) scans an application's own source for Altitude's rules that are certain from text: hard-coded colours instead of tokens (`ALT-TOKEN-001`), the stylesheet and `AltitudeProvider` (`ALT-SETUP-002`, `ALT-SETUP-003`), buttons labelled OK or Submit (`ALT-COPY-001`) and the chart rules certain from source: pie and donut charts (`ALT-CHART-001`), two value axes on one plot (`-002`), bars that don't stand on zero (`-003`), gradients, shadows and fully rounded bars on marks (`-004`), series coloured with the accent, a presence hue or a status colour, or shadcn's `--chart-*` not mapped to `data-*` (`-005`), a chart with no name (`-006`) and Recharts marks that animate in (`-007`). Those fail the run. Several primary buttons in one file (`ALT-PRIMARY-001`), elevation overrides on controls (`ALT-VISUAL-004`), the chart that leads a page with no takeaway (`ALT-CHART-008`) and three or more series with nothing said to matter (`ALT-CHART-009`) are listed for review and never fail. The stylesheet and the provider are app-wide, usually at the entry, so `ALT-SETUP-002` and `ALT-SETUP-003` are verified at project scope: when `[dir]` is a subtree such as `src/components` and imports components, the stylesheet import and `AltitudeProvider` are looked for across the whole project (the `--cwd` directory, skipping `node_modules`, `dist` and `build`), and they fail only when the project has none. Every other rule reports only inside `[dir]`. A finding a team keeps is marked `altitude-ignore: <ID> <reason>` on its line or the line above. It reads text only: nothing that needs the page rendered or a person is checked. Guidance remains usable offline through `altitude-design/guidance`, `altitude-design/guidance/*`, and physical `node_modules/altitude-design/dist/guidance` files. Tooling stays outside browser imports.
